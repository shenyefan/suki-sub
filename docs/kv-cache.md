# KV 缓存内容与更新规则

本次已将分享记录一次性迁入 D1 的 `share_tokens` 表。运行时不再读取或写入 KV 的 `token:<id>`；创建、删除、重命名和次数限制都以 D1 为准。

## 线上核对

2026-10-11 迁移前，当前项目 KV 中有 5 条分享和 2 条资源缓存。两条资源缓存均为订阅文本，整个缓存条目分别约 7.6 KB 和 10.2 KB，内部到期时间与 KV 的过期时间一致。线上没有设置 `resourceCacheTtl`、`headersCacheTtl`、`scriptCacheTtl` 或 `cacheThreshold`，使用代码默认值。以上是读取时的快照，资源缓存数量会随请求与过期变化。

清理前逐条核对了 D1 中分享的标识、目标、创建与过期时间、次数以及扩展字段，随后删除 5 条旧 KV 分享副本。清理后复查：KV 分享记录为 0 条，D1 分享仍为 5 条；订阅资源缓存未删除。迁移原始数据及校验结果已另存本机私有备份。

## 缓存类型

| 键前缀 | 内容 | 默认有效期 | 使用情况 |
| --- | --- | --- | --- |
| `#suki-sub-cached-resource:` | 原始订阅响应文本，以及域名解析结果 | 1 小时 | 下载引擎与 DNS 操作符实际使用 |
| `#suki-sub-cached-headers-resource:` | `subscription-userinfo`、套餐名称、网页地址组合成的流量头文本 | 1 分钟 | 流量查询和下载响应头实际使用 |
| `#suki-sub-cached-custom-` | 用户通过链接参数 `cacheKey` 指定的订阅文本 | 无自动过期 | 作为旧内容回退和乐观缓存；成功下载可覆盖 |
| `#suki-sub-cached-script-resource:` | 脚本资源 | 48 小时 | 有实现，目前没有实际调用点；脚本沙箱禁用此缓存接口 |
| `cache:resource:` | `{content, headers}` | 由写入者传入 | 存储层保留的工具函数，目前没有实际调用点 |

## 命中、过期与更新

- 普通订阅缓存的键是请求 UA（或自定义请求头）与实际请求 URL 拼接后计算的 MD5。同一 URL 使用不同 UA/请求头会得到不同缓存；DNS 操作符则按提供方、域名、记录类型等计算键。
- 资源、流量头和脚本缓存保存 `{time, data}`，其中 `time` 是绝对到期时间。读取先检查此时间，不会因为 KV 仍保留条目就使用已过期内容。
- 写入同时设置 KV `expirationTtl`。KV 最小有效期为 60 秒；如果用户指定更短时长，应用会按内部 `time` 提前停止使用，但 KV 原条目最多会多保留到 60 秒。
- 缓存命中直接返回原数据，不延长有效期。未命中或过期时请求上游，成功后覆盖缓存并重新计算到期时间。
- 下载成功也会用同一个请求身份更新流量头缓存。默认大于约 1024 KB 的响应不缓存；此阈值实际按文本字符数估算，而非 UTF-8 字节数。
- 普通订阅内容可通过链接参数 `cacheTtl`（秒）覆盖有效期，流量头可通过 `headersCacheTtl`（秒）覆盖。设置中的 `resourceCacheTtl`、`headersCacheTtl` 也使用秒；缓存类内部使用毫秒。DNS 操作符调用缓存时传入的是毫秒。
- `noCache` 会绕过旧内容并请求上游，但成功后仍更新缓存，不表示禁止写入。
- 手动“刷新流量”已改为传递 `noCache=true`，同时绕过前端与服务端流量缓存。普通页面流量查询仍有 5 分钟的前端新鲜期；后台流量头缓存默认只有 1 分钟，二者并非同一个缓存。
- 分享管理数据不再依赖 KV，KV 的跨节点同步延迟不会再影响分享创建、删除、重命名或次数判断。

## 当前机制的边界

- 缓存没有周期预热任务；请求到来时按需更新，KV 根据 TTL 自动清理。类中的 `_cleanup` 与 `revokeAll` 方法当前没有应用调用入口。
- `cacheKey` 自定义缓存没有 TTL，旧内容可在上游失败时继续回退。它的异步更新分支没有等待任务完成，也没有登记到 Workers `waitUntil`，因此不能保证响应结束后刷新仍会完成。
- KV 本身是最终一致的，缓存更新在其他节点可能稍后才可见。主动刷新直接使用当次上游结果，但另一节点的普通缓存读取仍可能在有效期内看到旧值。
- 修改 URL、UA 或自定义请求头会改用新键；旧缓存不会立即删除，普通缓存随 TTL 过期。相同请求身份下修改有效期设置不会追溯调整已经写入条目的到期时间。
- KV 缓存写入异常目前会向调用方传播，可能影响已经成功取得上游数据的下载或流量查询。此处记录现有行为，本次没有改变缓存失败策略或自定义缓存机制。
